## The open question: "AI tool" or "question-based search"?

Build it the way Greater Opportunities works (greaterops.org, repo at
`~/Sites/greaterops/greaterops`): **plain-language search with no AI model behind it**. A visitor
types a sentence in their own words and gets ranked, relevant pages. That delivers what "AI to
guide the user" is asking for, with no running cost and no wrong-answer risk. A true AI answer
stays available as an optional last step.

| Layer | What the visitor gets | What it runs on | Ongoing cost |
|---|---|---|---|
| 1. Plain-language search | Type a word or a full sentence ("we need help funding a water project"), get ranked results labelled by type, programs shown with their parent service | A cached server index of Directus content, ranked by weighted word matching, as on Greater Opportunities | None |
| 2. Guided entry | The five core services appear as example prompts and entry points in the search panel and on the Services page | The core services' own "need" lines | None |
| 3. Ask ST8 (AI), optional | A two or three sentence written answer above the results, linking to ST8 pages | The top results from layer 1 sent to Claude Haiku 5.5 | Per question, small; estimate it in session 12 |

What makes layer 1 feel guided is content, not code. Greater Opportunities gives each service and
program two extra fields: `need`, a phrase in the visitor's voice, and `search_phrases`, the words
people really type. Those are weighted above the title. Beth's keyword lists for the five core
services are exactly this material.

**Decided 2026-11-26: option (b),** built so the AI answer is on only when a model API key
environment variable is set. Without the key the site behaves as (a). Session 12 builds it.

### Two Directus instances

- `manage.southerntier8.org` (Directus 12.5): staff-managed content for ST8's own websites. This
  site reads only this one.
- `manage.so-tier.com`: partners and members who sign in and manage their own content across
  several sites (Insider, Summit, Portal). `@hue-studios/st8-layers` runs against this one.

So the layers are **not used here**. They are sign-in, social and network features over the
so-tier instance, and this site has no accounts. The dependency versions still match the layers'
peers, which costs nothing and keeps the ST8 projects on one stack. If this site ever needs a
member feature, it would talk to both instances: content from southerntier8, members from
so-tier through the layers. That is a separate project.

### Dark mode

The 8,100 lines of SCSS use fixed colours, so switching on dark mode today would give half-dark
pages. Tokens for both modes are defined from the start, new shadcn-based components are built to
work in both, and `colorMode.preference` is held at `light` with no toggle. A dark pass over the
SCSS is a separate job, not in this plan.
